# UX + Accessibility Audit — Clickit Story (CIT)
**Date:** 2026-05-30  
**Scope:** Viewer routes, all viewer components, i18n, accessibility, RTL, performance

---

## Summary

- **`LandingHeroAnimations` and `ScrollReveal` ignore `prefers-reduced-motion`** — both use `motion` animations (`y: 20 → 0`, `repeat: Infinity` bounce arrow, and `whileInView` slide-ups) with no reduced-motion guard, while the rest of the system (page transition, hero banner, smooth scroll, CinematicBackdrop) correctly implements the guard. The landing hero also hardcodes `autoplay=1` in the iframe URL server-side — no way to suppress for reduced-motion users because it is RSC.
- **Search page has 5 instances of hardcoded English strings** ("Search the catalog" ×4, "Watch catalog" ×1) bypassing `t()`. These render verbatim for Arabic users. Show card hover overlay also hardcodes "Play" and "New" badge.
- **Password show/hide button is RTL-broken** — positioned `absolute top-1/2 right-3`, which collides with text in Arabic RTL layout; must be `end-3` (logical property). Same issue in `signup-form.tsx` and `reset-password-form.tsx`.
- **No `error.tsx` boundary exists** anywhere in the viewer route tree — a runtime error in any server component (DB outage, bad data) produces a generic Next.js error page with no locale, no branding, and no navigation. Only the series slug 404 has a `not-found.tsx`.
- **`LandingHero` (RSC) hardcodes `autoplay=1` in the YouTube iframe URL** and `autoPlay` on the `<video>` element. The server component has no access to `usePrefersReducedMotion`; the iframe src is built at render time. Motion-sensitive users on the landing/portfolio page get autoplay video with no opt-out.
- **`animate-ping` (LIVE dot in navbar)** is a CSS animation with no `prefers-reduced-motion: reduce` suppression in globals.css or the component. Tailwind's `motion-reduce:` variant is not applied.

## Top 3 Quick Wins

**1. Wrap `LandingHeroAnimations` with `MotionConfig reducedMotion="user"`** (`src/components/landing/landing-hero-animations.tsx`) — one import + one wrapper component, kills the infinite bouncing arrow and all stagger animations for reduced-motion users. Five minutes.

**2. Fix password eye button RTL** — change `right-3` to `end-3` in `login-form.tsx`, `signup-form.tsx`, and `reset-password-form.tsx`. Three files, three find-replace operations. Fixes Arabic auth entirely.

**3. Fix search page hardcoded strings** — add two translation keys (`catalogEyebrow`, `watchCatalog`) to `en.json`/`ar.json`, replace the 5 hardcoded literals in `search/page.tsx`. Highest-traffic page after browse.

## Bigger Investments

**A. Landing hero reduced-motion for RSC video (M effort)**
`LandingHero` is a React Server Component — it cannot call `usePrefersReducedMotion`. Options: (1) Read a cookie set by a client component on first visit that signals reduced-motion preference to the server. (2) Split into `LandingHeroClient` that receives `ytId` as a prop and conditionally sets `autoplay=1` based on the hook. Option 2 is cleaner — move the iframe + video rendering to a `'use client'` child.

**B. Error boundary for viewer route tree (M effort)**
Add `src/app/[locale]/(viewer)/error.tsx` as a proper React error boundary (Next.js App Router client component with `useEffect` reset). Include the navbar-equivalent minimal header, a translated error message, and a link back to `/watch`. This prevents a full-white crash screen on any DB or fetch failure.

**C. Keyboard navigation for horizontal rails (M effort)**
`DragScroll` currently ignores keyboard. Add `role="list"` to the scroll container, `role="listitem"` to each card wrapper, and an `onKeyDown` handler that calls `trackRef.current.scrollBy({ left: ±300, behavior: 'smooth' })` on `ArrowLeft`/`ArrowRight`. This is a WCAG 2.1 Level A gap for content discovery.

**D. Full `<img>` → `next/image` audit (S/M effort total)**
`ShowCard` (main browse rail), `user-avatar.tsx`. Converting these adds WebP/AVIF at no code cost and eliminates the largest unoptimised images on the most-visited page. Estimated 30–60% file size reduction on hero/poster images.
