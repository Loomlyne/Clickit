<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → guard | Migration SQL and file names in a PR are untrusted text the guard parses |
| guard → git | Revision and path strings reach `git` as process arguments |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | migration SQL hiding a drop in a comment or string | mitigate | Scanner strips comments only; strings and `$$` bodies stay scanned (fixtures 10, 11); waiver must be a real comment on the same line with a non-empty reason (fixture 6) |
| T-01-02 | Tampering | applied migration silently edited/renamed/deleted | mitigate | D-05 rule on every non-A status; allow-list requires exact from and to blob SHAs (fixture 15) |
| T-01-03 | Elevation of privilege | shell injection via file names or `--base` | mitigate | `execFileSync('git', [...])` argument arrays, no shell, no `eval` (acceptance grep) |
| T-01-04 | Tampering | PR edits the guard itself to pass | accept | RESEARCH Pitfall 9: safety net for mistakes, not a boundary; every PR reviewed before Koss's Ship; recorded in the hand-over |
| T-01-05 | Denial of service | obfuscated SQL (`'dr'||'op'`) evades the guard | accept | Known gap from RESEARCH; guard catches mistakes, CLI dry-run + approval is the real gate |
</threat_model>
