<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR branch code → GitHub runner | Untrusted PR code runs in `pull_request` jobs of a public repo |
| Apply workflow → live Postgres | DB URL secret crosses into a runner that writes live schema |
| Dispatcher → approver | Whoever dispatches must not be able to self-approve as an agent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Information disclosure | pr-gate.yml | mitigate | `pull_request` (not `_target`), `permissions: contents: read`, no `secrets.` (test-enforced), `persist-credentials: false` |
| T-01-24 | Tampering | PR weakens the guard that judges it | mitigate | `migration-guard` runs the base branch copy via `git show HEAD^1:...` into `$RUNNER_TEMP` (test-enforced); PR copy only when base has none (Phase 1 PR) |
| T-01-07 | Tampering | third-party actions | mitigate | Full 40-hex SHA pins with version comments (test-enforced); no new action |
| T-01-08 | Tampering | unreviewed live DDL | mitigate | `workflow_dispatch` only, main-only step, dry-run first, `environment: live-db` reviewer, `pg_dump_taken` required, no include-all/include-seed (test-enforced) |
| T-01-09 | Information disclosure | DB URL in logs | mitigate | Secret only via env, GitHub masking, no debug flag (test-enforced), `tee` writes CLI output only |
| T-01-10 | Elevation of privilege | apply runs if `live-db` environment is missing (auto-created without reviewer) | mitigate | Runbook (plan 04) creates and reads back `live-db` with reviewer before the first dispatch; header comment states it |
| T-01-11 | Denial of service | required check never reports on docs-only PRs | mitigate | No workflow-level path filter; `scope` step + step-level `if` |
| T-01-12 | Elevation of privilege | agent approving its own gate | mitigate | Procedure in runbook: Koss approves in the Actions UI; controller never calls the pending_deployments API |
</threat_model>
