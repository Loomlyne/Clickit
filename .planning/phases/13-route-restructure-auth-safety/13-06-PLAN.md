  <how-to-verify>
    **Deploy the Phase 13 branch to a Vercel preview:**

    ```bash
    vercel
    ```

    Use `vercel` (NOT `vercel --prod`). The preview URL will be of the form `https://clickit-cit-{hash}.vercel.app`. Wait for the build to complete (green check in dashboard or CLI exit 0).

    **IMPORTANT — Vercel SSO protection:** If the preview URL returns 401, the project has `ssoProtection: 'all_except_custom_domains'` active. Either:
    - Use `vercel curl <preview-url>` which handles the deployment-auth token
    - Or use the Vercel dashboard's "Access preview" link (authenticates via team SSO)

    **If the preview URL returns `NOT_FOUND` on every path:** the project framework preset is null. Fix via the Vercel API (memory: `curl -X PATCH .../projects/<id> -d '{"framework":"nextjs"}'`, then `vercel --prod --force`).

    **Then walk through this 10-item checklist on the preview URL.** Each item must PASS before merging.

    ### 1. Root redirect preserves locale prefix
    - Visit `/` (bare root)
    - Expected: 302 redirect to `/en/` (defaultLocale)
    - Check devtools → Network → first document response: Location header `/en`

    ### 2. /ar/ renders with correct direction
    - Visit `/ar/`
    - Expected: page loads, devtools → Elements → `<html lang="ar" dir="rtl">`
    - Content is still English strings (translation is Phase 15) — this is OK

    ### 3. Sign in on /en/auth preserves locale
    - Visit `/en/auth`, sign in with a known account
    - Expected: after successful sign-in, redirect to `/en/` (or `/en/admin` if admin)
    - URL MUST start with `/en/` — NOT bare `/auth/login` or bare `/`

    ### 4. Sign in on /ar/auth preserves locale
    - Visit `/ar/auth`, sign in with same account
    - Expected: redirect to `/ar/` (or `/ar/admin`)
    - URL MUST start with `/ar/` — locale PRESERVED through server action + client navigation

    ### 5. Locale switch from profile page persists session
    - Sign in, visit `/en/profile`
    - Click Arabic option in Language section
    - Expected: URL changes to `/ar/profile`
    - Devtools → Application → Cookies: `sb-...-auth-token` cookie STILL present (session preserved)
    - This is the Pitfall-1 smoke test — if the cookie disappears, the proxy cookie-merge is broken

    ### 6. Show card click preserves locale
    - On `/en/browse`, click any show card → expect `/en/series/<slug>`
    - Navigate to `/ar/browse`, click same show → expect `/ar/series/<slug>`
    - Every show card uses `<Link>` from `@/i18n/navigation` now — NO bare `/series/...` navigation

    ### 7. Watch page prev/next preserves locale
    - On `/en/watch/<id>`, use prev/next controls → URL stays on `/en/watch/<other-id>`
    - Switch to `/ar/watch/<id>`, use prev/next → URL stays on `/ar/watch/<other-id>`

    ### 8. Coming-soon gate preserves locale (requires admin to toggle flag)
    - Sign in as admin, visit `/en/admin/settings` → Advanced tab
    - Toggle "Coming Soon mode" ON, save
    - Sign out (or open incognito window on the preview URL)
    - Visit `/ar/browse` (a gated path) → expected redirect to `/ar/coming-soon` (not bare `/coming-soon`)
    - Visit `/browse` with no prefix → expected redirect to `/en/coming-soon` (defaultLocale)
    - **RESET** — Sign back in as admin, toggle Coming Soon OFF before finishing

    ### 9. Sitemap contains language alternates
    ```bash
    curl -s <preview-url>/sitemap.xml | head -50
    ```
    Expected: at least one `<xhtml:link rel="alternate" hreflang="ar" href="..." />` tag visible in the output. Every `<url>` block should have both `hreflang="en"` and `hreflang="ar"` alternates.

    ### 10. OAuth callback lands on locale-prefixed URL
    - If Google OAuth is configured on the preview:
      - Visit `/en/auth`, click "Sign in with Google"
      - Complete the Google flow → expected landing on `/en/...` (the `?next=` target, locale-prefixed by safeNext)
    - Also verify error case:
      - Visit a malformed callback URL directly, e.g., `<preview-url>/auth/callback?error=test`
      - Expected: redirect to `/en/auth?error=Could not verify your identity` (or `/ar/auth?error=...` if NEXT_LOCALE cookie is 'ar')

    ### If ANY item fails:
    - Note the failure, the item number, and the observed vs expected behavior
    - Do NOT merge to main
    - Return to the relevant plan (13-02 for 1/5/8, 13-03a/13-03b for 3/4/6/7, 13-04 for 10, 13-05 for 9) and iterate
