<interfaces>
Variant key layout (shared contract with the copy script in plan 02-08 and browser uploads in plan 02-17; Claude's discretion per CONTEXT, fixed here): original at <bucket>/<key>; variants at _v/<width>/<format>/<bucket>/<key> where width is 640, 1280 or 1920 and format is avif or webp. The variant object keeps the original key's file name (extension is not changed); its httpMetadata.contentType is image/avif or image/webp.

R2 Workers API used (research Pattern 2): MEDIA.get(key, { range: request.headers, onlyIf: request.headers }) returns null (missing), an R2Object without body (precondition failed) or an R2ObjectBody (has body; obj.range is {offset,length} or {suffix} when a range applied); MEDIA.head(key); obj.writeHttpMetadata(headers); obj.httpEtag; obj.size. The Cloudflare docs sample never sets 206/Content-Range: this handler must.

Cache-Control rule (research Code Examples): "?v=" present or a variant served -> public, max-age=31536000, immutable; otherwise public, max-age=3600.
</interfaces>
