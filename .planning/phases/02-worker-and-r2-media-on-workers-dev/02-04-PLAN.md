<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> cron routes | anyone can call /api/cron/* with a guessed Bearer |
| client headers -> rate limiter | X-Forwarded-For is attacker-controlled |
| browser token -> siteverify | token can be replayed or forged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Spoofing | cron secret timing | mitigate | SHA-256 both sides, timingSafeEqual on equal 32-byte digests; no === on secret material |
| T-02-14 | Spoofing | rate-limit bypass via XFF | mitigate | only cf-connecting-ip is read; validated as an IP |
| T-02-15 | Denial of service | limiter failing open under store errors | mitigate | every error path refuses (fail closed) |
| T-02-16 | Spoofing | Turnstile token replay/forgery | mitigate | server siteverify with remoteip; any non-success refuses; 5 s timeout refuses |
| T-02-17 | Information disclosure | secret/token in logs | mitigate | no console calls in turnstile.ts; tests assert the secret never appears in thrown messages |
</threat_model>
