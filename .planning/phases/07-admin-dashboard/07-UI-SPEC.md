# Phase 7 — UI Design Contract

> Visual and interaction contract for the admin dashboard. Generated by gsd-ui-researcher.
>
> Phase 7 is a **functional admin tool** — table-focused, drawer-based CRUD, no cinematic hero banners. The dark CIT theme carries forward but the layout language shifts from immersive streaming UI to productive data management. All tokens inherited from Phase 1 design system; this contract specifies the admin-specific interaction patterns, component inventory, and copywriting.

## Typography

| Role | Size | Weight | Line Height | Usage in Admin |
|------|------|--------|-------------|----------------|
| Body | 16px | 400 (Regular) | 1.5 | Table cell content, form field values, drawer body text |
| Label | 14px | 400 (Regular) | 1.4 | Table headers, form labels, metadata captions, breadcrumbs |
| Heading | 20px | 600 (Semibold) | 1.2 | Page titles ("Shows", "Archive"), drawer titles ("Edit Show") |
| Display | N/A | N/A | N/A | Not used — no display-size text in admin dashboard |

**Weight note:** Admin uses 400 (Regular) + 600 (Semibold) for functional hierarchy. The Phase 1 contract specified 400 + 700 (Bold) for cinematic pages. Admin headings use 600 (Semibold) because the admin context is utilitarian — Bold (700) feels heavy for dashboard page titles. The font files loaded (Inter variable) support both weights without additional network requests.

## Layout Contract

### Admin Shell Structure

```
/admin (layout.tsx)
+------------------------------------------+
| Admin Header: "CIT Admin" + nav tabs     |
| [Shows] [Archive]                        |
+------------------------------------------+
| Page content (table or detail)           |
|                                          |
|                                          |
+------------------------------------------+
```

- **No sidebar.** Admin has a simple top nav with two tabs: "Shows" and "Archive". The main CIT viewer navbar is hidden on `/admin` routes (admin layout replaces it).
- **Admin header:** Left-aligned "CIT Admin" text (20px, semibold). Right-aligned: admin avatar from existing auth. Below: horizontal tab nav for Shows | Archive.
- **Full-width content area.** Tables use the full viewport width with `max-w-7xl mx-auto` constraint and `px-4 md:px-8` horizontal padding.
- **Primary visual anchor:** The "Create Show" button at top-right of the show list page -- the only filled accent-color element on an otherwise functional, neutral-toned page. On first load, this is the focal point that draws the admin's eye and communicates the primary action.

### Route Structure

| Route | Content |
|-------|---------|
| `/admin` | Show list table (active shows, `archived = false`) |
| `/admin/shows/[id]` | Show detail: season tabs with episode lists |
| `/admin/archive` | Archived shows table (soft-deleted, `archived = true`) |

### Table Layout (D-03)

**Show List Table columns:**

| Column | Width | Content |
|--------|-------|---------|
| Show Name | flex (fills remaining space) | Title text, left-aligned |
| Genre | 120px | Genre text |
| Status | 120px | Badge component |
| Episodes | 80px | Count number |
| Broadcast | 140px | Day + time (e.g. "Monday 20:00") |
| Actions | 100px | Edit button, Archive button |

- Table rows: `h-14` (56px) for comfortable click targets
- Alternating row backgrounds: odd rows `var(--background)`, even rows `var(--card)`
- Hover state: `var(--accent)` / `#242430`
- No horizontal scrolling at `>= 768px` (md breakpoint). Below 768px, table scrolls horizontally inside a container with `overflow-x-auto`.

### Show Detail Page Layout (D-01, D-02)

```
/admin/shows/[id]
+------------------------------------------+

| Season tabs: [S1] [S2] [S3] ...         |
+------------------------------------------+

| Episode table for selected season        |
| - Episode # | Title | Duration | Status  |
| - Actions: Edit, Up, Down, Archive       |
+------------------------------------------+
| [+ Add Season] button                    |
+------------------------------------------+
```

**Episode Table columns:**

| Column | Width | Content |
|--------|-------|---------|
| # | 48px | Episode number |
| Title | flex (fills remaining) | Episode title |
| Duration | 80px | Minutes |
| YouTube | 80px | Thumbnail or video ID badge |
| Status | 100px | Badge |
| Actions | 160px | Edit, Up arrow, Down arrow, Archive |

### Archive Table Layout (D-04)

Same structure as Show List Table but with different action columns:

| Column | Width | Content |
|--------|-------|---------|
| Show Name | flex | Title text |
| Genre | 120px | Genre text |
| Archived Date | 140px | Formatted date |
| Actions | 180px | Restore button (outline), Permanently Delete button (destructive) |

## Interaction Patterns

### Slide-Out Drawer (D-05, D-06, D-07)

**All create/edit operations use the shadcn Sheet component.**

| Property | Value |
|----------|-------|
| Side | right |
| Width | `sm:max-w-lg` (512px on desktop), full-width on mobile |
| Background | `var(--card)` / `#1A1A22` |
| Border-left | `1px solid var(--border)` / `#2A2A36` |
| Close trigger | X button in top-right corner + clicking outside |

**Drawer sections (top to bottom):**
1. **Header:** Title ("Create Show" / "Edit Show" / "Create Episode" / etc.) at 20px semibold
2. **Body:** Scrollable form fields with 24px vertical gaps between field groups
3. **Footer:** Sticky bottom bar with Discard Changes (ghost button) + entity-specific save (primary button: "Save Show", "Save Season", or "Save Episode")

**After save:** Drawer closes. Sonner toast appears at bottom-right. Table refreshes with updated data.

### YouTube URL Extraction (ADMN-09)

- Input field label: "YouTube URL"
- Placeholder: "Paste YouTube URL (e.g., youtube.com/watch?v=...)"
- On `onChange`: extract 11-char video ID from URL using regex supporting formats: `youtu.be/ID`, `youtube.com/watch?v=ID`, `youtube.com/embed/ID`, `youtube.com/shorts/ID`
- Below input: if valid ID extracted, show YouTube thumbnail preview at 120x68px (`https://img.youtube.com/vi/{ID}/mqdefault.jpg`) with video ID in muted text
- If invalid URL: show validation error "Could not extract video ID from this URL"

### Artwork Upload (D-09, D-10, D-11)

Three upload zones inside the show drawer, stacked vertically:

| Zone | Label | Aspect Hint | Max File Size |
|------|-------|-------------|---------------|
| Poster | "Poster Image" | 2:3 portrait | 5MB |
| Hero Banner | "Hero Banner" | 16:9 landscape | 5MB |
| Logo | "Show Logo" | free-form (PNG with transparency) | 2MB |

**Upload zone states:**

1. **Empty:** Dashed border (`var(--border)`), centered upload icon (lucide `Upload`), text "Click to upload" at 14px muted
2. **Uploading:** Progress spinner (lucide `Loader2` with `animate-spin`), "Uploading..." text
3. **Uploaded:** Image preview filling the zone with a "Replace" button overlaid at bottom-right

**Behavior (D-10):** File uploads immediately on file selection to Supabase Storage. Preview appears when upload completes. Storage path written to DB on form save. If admin closes drawer without saving, the uploaded file remains in storage (orphan — acceptable per D-10 trade-off).

### Episode Reordering (D-08)

- Each episode row has Up (lucide `ChevronUp`) and Down (lucide `ChevronDown`) icon buttons
- First episode: Up button disabled (muted, no click handler)
- Last episode: Down button disabled
- Click triggers immediate server action: swap `episode_number` with adjacent row, table re-renders
- No toast on reorder (too frequent) — visual reorder is sufficient feedback

### Archive Flow (D-15, D-18)

1. Admin clicks "Archive" on a show row
2. Confirmation dialog appears (shadcn Dialog):
   - Title: "Archive Show"
   - Body: "This will hide [Show Name] from all viewers. You can restore it from the Archive section."
   - Actions: Cancel (outline) | Archive Show (destructive variant)
3. On confirm: server action sets `archived = true`, row disappears from show list, toast: "Show archived"

### Permanent Delete Flow (D-19)

1. From Archive table, admin clicks "Delete Permanently" on a row
2. Confirmation dialog (shadcn Dialog):
   - Title: "Permanently Delete Show"
   - Body: "This will permanently delete [Show Name] and all its seasons and episodes. This action cannot be undone."
   - Actions: Cancel (outline) | Delete Permanently (destructive variant)
3. On confirm: server action cascade-deletes show + seasons + episodes + storage files, row disappears, toast: "Show permanently deleted"

### Restore Flow

1. From Archive table, admin clicks "Restore" on a row
2. No confirmation needed — restoration is non-destructive
3. Server action sets `archived = false`, row moves from archive to show list, toast: "Show restored"

## Accessibility Notes

- All form inputs have associated `<label>` elements (via shadcn Form component)
- Table uses semantic `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` elements
- Action buttons have `aria-label` when icon-only (e.g., Up/Down arrows: `aria-label="Move episode up"`)
- Dialog components trap focus and support Escape to close (Radix Dialog behavior)
- Sheet drawer supports Escape to close and focus trapping (Radix Sheet behavior)
- Status badges use `aria-label` for screen readers (e.g., `aria-label="Status: Now Streaming"`)
- Destructive buttons use `variant="destructive"` for visual distinction — no color-only communication; button text explicitly states the action
- Image upload zones are keyboard-accessible (triggered by Enter/Space on the zone)
