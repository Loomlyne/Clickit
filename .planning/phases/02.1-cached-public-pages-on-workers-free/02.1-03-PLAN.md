<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenNext render -> Workers Cache | Whatever headers leave the Pages entrypoint decide what is stored and shared |
| Workers Cache -> browser | Stored headers must not reach browsers verbatim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-20 | Information disclosure | cross-user leak via a stored user-class redirect or dynamic render | mitigate | Store only shareable 200s and anon redirects; user redirects and private responses get private, no-store |
| T-02.1-21 | Information disclosure | cookie leakage through stored Set-Cookie | mitigate | Set-Cookie always removed before storing; gateway adds only NEXT_LOCALE |
| T-02.1-22 | Tampering | cache poisoning via absolute Location or Link built from the first requester's host | mitigate | Same-origin Location made relative; other-origin Location not stored; Link removed |
| T-02.1-23 | Tampering | open redirect stored for everyone | mitigate | Only same-origin relative redirects are stored; ?next= values are already filtered by key.ts |
| T-02.1-24 | Denial of service | fragmentation through Vary | mitigate | Vary removed from stored responses, restored for browsers |
| T-02.1-25 | Spoofing | forged or expired JWT | accept | Not decided here; class comes from session.ts; this module only enforces per-class storage rules |
</threat_model>
