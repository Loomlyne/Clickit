<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| x-clickit-class header -> proxy gates | Trusted only on the cached path (no cookies, gateway-set) |
| ?next= -> redirect Location | Attacker-controlled input into a redirect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-60 | Spoofing | forged x-clickit-class: user on a direct request | mitigate | readTrustedClass refuses when any cookie or authorization is present; the gateway strips inbound x-clickit-* on every path (02.1-06); a forged user class could at most show a static, user-independent shell |
| T-02.1-61 | Spoofing | forged or expired JWT on the cookies path | mitigate | Unchanged getClaims verification in updateSession |
| T-02.1-62 | Tampering | open redirect via ?next= on signed-in /auth | mitigate | getSafeAuthNextPath (same as today) and a locale prefix; never an absolute URL |
| T-02.1-63 | Tampering | browse ?category= injection into Location | mitigate | isCategorySlug allowlist; anything else drops the parameter |
| T-02.1-64 | Elevation of privilege | admin gate on the cached path | mitigate | checkIsAdmin is false on the header path; /admin never reaches it (gateway deny) |
| T-02.1-65 | Information disclosure | cookie leakage / cross-user leak | mitigate | Header path creates no Supabase client and sets no session cookies; redirect responses for user class are never stored (02.1-03) |
</threat_model>
