#### Gateway (default fetch entrypoint, Workers Cache off)
- **D-10 Hard deny.** These go straight to OpenNext and are never cacheable: `/admin*`, `/<locale>/admin*`, `/auth/callback`, `/api/*`, non-GET/HEAD requests, any `next-action` header, and `/<locale>/auth*` **for the signed-in class only**.
- **D-11 Bare `/` and unprefixed paths.** The gateway answers a 307 to `/<locale><path><query>`. The locale is the NEXT_LOCALE cookie if it is en/ar, else Accept-Language negotiation, else en. The proxy is not invoked and the redirect is not cached. Excluded: `/api`, `/auth/callback`, `/_next`, files with an extension, `sitemap.xml`, `robots.txt`.
- **D-12 Verified class.** The gateway rebuilds the Supabase auth cookie (chunked `.0/.1`, `base64-` prefix) and verifies the JWT locally: ES256 against the project JWKS, cached per isolate, the same check as `getClaims()`.
  - Valid → `user`.
  - Auth cookie present but invalid, expired or unverifiable → bypass to OpenNext, where the proxy refreshes or clears it.
  - Only `sb-…-code-verifier`, or no auth cookie → `anon`.
  - Cookie presence alone never makes `user`.
- **D-13 Key.** `cf.cacheKey = /__c/<class>/<rsc-kind>/<segment-prefetch>/<path>?<allowlisted params sorted>`.
  - `_rsc` is stripped.
  - `utm_*`, `fbclid`, `gclid` and `msclkid` are removed from the URL itself before the render, so no stored body or `Location` carries a visitor's query (this fixes the e49a219 308 bug).
  - `next` (auth) is kept only when `getSafeAuthNextPath` accepts it, and `category` (browse) only when it passes its sanitizer; any other value bypasses.
  - No device dimension.
- **D-14 Strip.** For cacheable requests the gateway removes `Cookie`, `Authorization` and `Accept-Language` before calling the cached entrypoint. It sets `x-clickit-class: user|anon` and drops any inbound copy of that header. On that path the proxy's gates read only the class header.

#### Cached entrypoint (OpenNext behind `ctx.exports`, Workers Cache on)
- **D-20** Cacheable responses carry `Cache-Control: max-age=<long>, stale-while-revalidate, stale-if-error` and `Cache-Tag`. Everything else is `no-store`.
- **D-21** The `user` class never stores redirects. Gate 307s are cached only for `anon`.
- **D-22 Fill on Free.**
  - Fills run in the cached entrypoint's own invocation.
  - Content saves use `ctx.cache.invalidate()` (stale-while-revalidate), not purge, so the old copy is served until a refill succeeds, indefinitely. `stale-if-error` covers a refill that ends in 1102.
  - Public pages are prerendered at build (`generateStaticParams`, ISR entries populated at deploy) so most fills are a cache read plus the proxy.
  - A post-deploy seeding script, run by the controller, fills the version-keyed cache: every URL × class × locale, retried until it is served from the cache.
- **D-23 Freshness.**
  - Invalidation is by content tags only: `site-config`, `shows`, `episodes`, `shorts`, `seasons`, `categories`, and the FAQ/legal `revalidatePath` calls. `profile/actions.ts` does not invalidate shared entries.
  - The coming-soon toggle (`updateFeatureFlags` → `bumpSiteConfigCache`) purges instead of invalidating, so it takes effect at once.
  - Invalidations are debounced: Workers Cache uses the Free purge limit of 5 tag requests a minute per account.
- **D-24** No `cookies()`, `headers()` or server Supabase client in any cached route's import graph. A test enforces it.

#### Tests (named, required)
- **D-40** These tests are required:
  - **Forged and invalid cookies.** A forged `Cookie: sb-x=1` gets anon. A JWT signed with another key bypasses. Neither ever gets the user shell or a cached `/watch/<episode>` body.
  - **Expired JWT** with a valid signature: bypass to the proxy, not cached.
  - **Code-verifier cookie only:** anon.
  - **Admin and non-admin signed in:** the same viewer shell; `/admin*` is never cached; the Admin menu entry comes from the browser.
  - **Redirects:** none stored in class `user`. Anon 307s are stored, and the coming-soon toggle purges them.
  - **Hard-deny list:** always OpenNext, `no-store`.
  - **Poisoning:** the same URL with varied Accept-Language, Cookie, User-Agent, X-Forwarded-Host, Forwarded and Next-Url gives an identical body before a route joins the cache.
  - **Byte-identical anon HTML:** two different anon requests get byte-identical HTML apart from the allowed key parts (controller condition).
  - **RTL:** a stored /ar body has `lang="ar" dir="rtl"`, a stored /en body `lang="en" dir="ltr"`.
  - **Bare and unprefixed paths:** a 307 by cookie, then Accept-Language, then en; not cached; proxy not invoked.
  - **Query handling:** `_rsc` is stripped; utm is absent from stored bodies and `Location` headers.
  - **Import graph:** no `cookies()`, `headers()` or server Supabase client in cached routes.
  - **Invalidation scope:** a profile action does not invalidate shared entries; a content action does.
  - **Long session:** local Supabase with a 60 s JWT, two tabs, 15 minutes of mixed cached and bypassed pages. The user stays signed in, with no `refresh_token_already_used`.

## Summary

The route is feasible on the evidence, with one design: **prerender every public page at build, keep the files in Workers static assets under a private prefix, and put a small gateway in front that decides wall, coming-soon and hidden state, then returns the file through the `ASSETS` binding.** Static asset requests are free and unlimited and invoked no Worker in the spike (50 requests, 0 invocations). The gateway hit path measured 0-2 ms in the spike; adding a session check, one small state read and an asset fetch is expected to stay under 10 ms, but that exact path has not run on Cloudflare, so the first deployable plan proves it with a throwaway probe Worker before any page is touched.

Rebuilds use **Workers Builds with a Deploy Hook on a dedicated pin branch**, debounced by one small Durable Object that also holds the status the admin bar reads. Build outcomes arrive through a Queues event subscription, so no token is needed at runtime. A clean-build test today showed the same commit produces **different** action ids, build id and 23 static files unless `generateBuildId` and `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` are pinned; with both pinned, two builds in different folders were identical. That pin is mandatory, or every rebuild breaks open tabs.

The biggest risk is not the public pages. **D-75 is likely to fail as written**: admin pages, saves, sign-in and the contact form still run a full Next render, and the measured 1102 rate for that is 43% (64 of 150) up to 100% once the allowance is spent. Run the stop line first, on today's workers.dev version, before building anything. If it fails, Koss decides on Workers Paid before the page work is spent.

**Primary recommendation:** Plan 1 is the D-75 harness run on the current workers.dev version; Plan 2 is the gateway probe proving D-73 and the assets path on Free; only then build gateway + static pages + Workers Builds.

## Architectural Responsibility Map

| Capability | Primary Tier | Secondary Tier | Rationale |
|------------|-------------|----------------|-----------|
| Page HTML and RSC | CDN / Static (Workers static assets) | Build (prerender) | Free, unlimited, no render on request |
| Wall, coming-soon, hidden, locale redirects | Gateway Worker | - | Must run before a file is returned, under 10 ms |
| At-once state | Object storage (R2 object) | Isolate memo in gateway | Strongly consistent, already bound, no extra Worker request |
| Personal state (avatar, list, like, progress, resume) | Browser (Supabase client + RLS) | - | Already browser-side writes; no Worker request |
| Video link | Database function behind `episodes_view`, read at build or by browser | - | Function compares `publish_at` to DB `now()` |

### Pattern 1: Wrangler config for private page files
**What:** Files live under `/__pages/`, so no public path matches them by accident. `run_worker_first` sends direct requests for that prefix to the gateway, which refuses them. Everything else stays asset-first, then falls to the Worker when no file matches.

```jsonc
// Source: developers.cloudflare.com/workers/static-assets/binding (2026-10-12), /routing/advanced/html-handling (2026-04-23)
{
  "minify": true,
  "assets": {
    "directory": ".open-next/assets",
    "binding": "ASSETS",
    "run_worker_first": ["/__pages/*"],
    "html_handling": "none",          // else /x.html answers 307 to /x, and binding calls get this too
    "not_found_handling": "none"
  },
  "migrations": [
    { "tag": "v1", "new_sqlite_classes": ["DOQueueHandler"] },
    { "tag": "v2", "new_sqlite_classes": ["RebuildCoordinator"], "deleted_classes": ["DOQueueHandler"] }
  ]

```
`html_handling` and `not_found_handling` apply to `env.ASSETS.fetch()` too [CITED: binding docs]. `_headers` rules are not applied to Worker responses, so the gateway sets every header itself [CITED: headers docs 2026-09-22]. Negative `run_worker_first` patterns exist; they are not needed here. At most 100 entries.

### Pattern 2: Request kinds to files
Next writes each static route as `<route>.html`, `<route>.rsc`, `<route>.meta` and `<route>.segments/` under `.next/server/app`, listed in `.next/prerender-manifest.json` with `dataRoute` and `initialRevalidateSeconds` [VERIFIED: scratch build 16.4.2, `_not-found`, 2026-10-31]. Route groups and `[locale]` file naming are expected to be `en/portfolio.html`; confirm at the first static build [ASSUMED].

| Request | File | Content-Type | Extra headers from `.meta` |
|---------|------|--------------|---------------------------|
| no `rsc` header | `/__pages/<path>.html` | `text/html; charset=utf-8` | none |
| `rsc: 1` | `/__pages/<path>.rsc` | `text/x-component` | `x-nextjs-stale-time`, `x-nextjs-prerender` |
| `next-router-segment-prefetch: <seg>` | `/__pages/<path>.segments/<seg>.segment.rsc`, or 204 when missing | `text/x-component` | same |

Set `Content-Type` in the gateway; wrangler infers it from the extension and `.rsc` will not be `text/x-component` [ASSUMED; the client falls back to a hard navigation on a wrong type]. `Vary: RSC, Next-Router-State-Tree, Next-Router-Prefetch, Next-Router-Segment-Prefetch, Next-Url` stays for browsers (v1 F2). Spike a stands: RSC payloads were byte-identical across state-tree and next-url variants, and `_rsc` plays no part on this path because Next never sees the request.

### Pattern 4: Debounce and status as one pure state machine
```ts
// src/server/rebuild/state-machine.ts (shape). Pure; the DO only persists and performs the returned actions.
type S = {
  phase: 'idle' | 'waiting' | 'building' | 'failed'
  firstSaveAt: number | null; lastSaveAt: number | null
  dirty: boolean; attempt: number; startedAt: number | null
  liveThrough: number | null          // lastSaveAt covered by the last success
  nextPublishAt: number | null
}
type Ev =
  | { t: 'save'; now: number; nextPublishAt: number | null }
  | { t: 'alarm'; now: number }
  | { t: 'build'; outcome: 'started' | 'success' | 'failure' | 'canceled'; now: number }
  | { t: 'retry'; now: number }
// save: waiting, alarm = min(lastSave + 3 min, firstSave + 15 min); while building: dirty = true
// alarm in waiting: POST hook, building, watchdog alarm +25 min
// failure or watchdog: attempt 1 -> POST hook again; attempt 2 -> failed
// success: liveThrough = lastSaveAt; dirty ? waiting (+1 min) : idle; then alarm at nextPublishAt + 2 min if set
```
Status for the bar: `waiting|building` → Waiting; `failed` → Failed; `idle` → Done. "Done" also requires the running Worker's baked `contentBuiltAt` to be at or after `liveThrough`, so the bar never says live before the new version answers.

### Anti-Patterns to Avoid
- **Putting pages at their public path in assets.** A file at `/en/watch.html` would be served without the gateway: no wall, no coming-soon, no hide. Keep the `__pages` prefix and a test that no HTML file sits outside it.
- **Enabling the Workers Builds cache.** `.next/cache` carries `unstable_cache` results across builds and can freeze old content. It is off until enabled [CITED: build-caching 2026-09-10]. Leave it off.
- **`catch { return [] }` in `generateStaticParams` on a deployable target.** A Supabase error would deploy an empty site. See Pitfall 2.
- **Letting `dynamic` default on public pages.** Set `export const dynamic = 'error'` and `dynamicParams = false`, so a stray `cookies()` fails the build instead of quietly making a route dynamic.
- **Static import of `.open-next/worker.js` in `custom-worker.ts`.** Today's entry does this (`custom-worker.ts:4`). It evaluates the 2.6 MB middleware bundle in every isolate. Lazy-import it, and lazy-import the email consumer too.
- **Hand-written copy of the proxy's gate order in the gateway.** Extract one pure module, and test parity.

## Common Pitfalls

### Pitfall 1: A page quietly stays dynamic
**What goes wrong:** one `cookies()`, `headers()`, `searchParams` or un-localed `getTranslations` makes a route dynamic: no file, and the gateway returns 404 for a real page.
**How to avoid:** `dynamic = 'error'` on public pages; Plan 11's check compares the expected route list to `prerender-manifest.json`. See v1 § Static rendering for today's causes; add `getAdminStatus` in `/auth`.
**Warning signs:** `ƒ` in the `next build` route table.

### Pitfall 2: Empty catalog goes live
**What goes wrong:** `createCatalogClient` returns null without a key, and queries return `[]` on error. A rebuild then publishes an empty site over a good one.
**How to avoid:** `content-build.mjs` fails before deploy unless: Supabase is the live URL (F6), the service key is present, and page counts per kind match a fresh DB count. Failure leaves the last version live, and the bar says so.
**Warning signs:** sudden drop in the `__pages` file count; compare to the last build.

### Pitfall 3: Rebuild overwrites a newer code deploy
**How to avoid:** the live-commit check immediately before `wrangler deploy` (Q3). Pause the DO during a code ship if the window worries the controller. Workers Builds' own deploy overlaps nothing else because Free allows one build.

### Pitfall 4: Skew after a rebuild
Covered by Pattern 3. **Warning signs:** "Failed to find Server Action" in logs; 404s on `/_next/static/chunks`.

### Pitfall 5: Wrangler refuses or breaks on DO removal
A class removed from code with no `deleted_classes` migration fails the deploy. `migrations` currently sits only at top level. My size build dropped them for a dry run only; a real deploy needs the v2 migration, and `env.production` needs reviewing.

### Pitfall 6: `run_worker_first` and asset path edge cases
`html_handling: none` is required, or `/x.html` answers 307. Files with no extension (`_tree`) and names with `(`, `[` need testing. Also `/sitemap.xml` and the `robots.txt` copy must sit at the root, not under `__pages`.

### Pitfall 7: Coming Soon flag baked into HTML
`viewer-shell` and `/auth` read `flags.comingSoonMode` at build (`(viewer)/layout.tsx:46`, `auth/page.tsx:80`). After an at-once switch the redirect works immediately, but the minimal header and `-mt-16` on `/auth` update only after the rebuild. Accept (D-73 "everything else waits"); or derive it in the browser. Mention in UAT.

### Pitfall 8: Admin saves look fine locally
Local workerd has no real Workers Builds, event subscription or R2 latency. Test the state machine purely, the DO through `wrangler dev`, and the real chain only at Plan 12.

### Pitfall 9: Long-session race on live paths
Hits no longer rotate tokens, but admin pages and actions still run `updateSession`. Browser and proxy can both refresh. D-40's long-session test remains required, now with mixed static and admin pages.

### Pitfall 10: 02.1-UI-SPEC "Other visible effects" go stale
Replace them: 404 for new links until rebuilt, Waiting bar, `next` in browser, email page timing.

### Pitfall 11: Next's `x-action-revalidated`
`revalidatePath` in any action makes the client refresh its current route: one more RSC request, a live render on admin. Each admin save is therefore 2 live invocations. Count that in D-75.

## Code Examples

### Gateway decision (shape, not run)
```ts
// src/server/gateway/index.ts. Pure, deps injected, so node:test covers it.
export async function handleGateway(req: Request, d: Deps): Promise<Response> {
  const url = new URL(req.url)
  const r = classifyRoute(url.pathname, req.method, req.headers)      // no I/O
  if (r.kind === 'live') return d.openNext(req)
  if (r.kind === 'deny') return notFound()
  if (r.kind === 'redirect') return redirect(r, req)                   // bare path, /auth/confirm, /browse
  if (r.kind === 'status') return d.rebuildStatus(req)

  const state = await d.gateState()                                    // memo -> R2 -> last -> baked
  const gate = decideGate(r.pathWithoutLocale, r.locale, state, url)   // same module as proxy
  if (gate) return redirect(gate, req)
  if (isHidden(r, state)) return d.page404(r.locale, req)

  const session = await d.classify(req.headers.get('cookie'))
  if (!isPublicPath(r.pathWithoutLocale) && !passesWall(session)) {
    return authRedirect(r)                                             // /<l>/auth?next=<path>, like proxy.ts:167-173
  }
  if (r.pathWithoutLocale === '/auth' && session.cls === 'user') return d.openNext(req)

  const res = await d.assets(assetPath(r, req.headers, url))
  return res.status === 404 ? d.page404(r.locale, req) : decorate(res, r, req)
}
```

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| **Leaked unreleased video link** in page, RSC, metadata or JSON-LD | Info disclosure | Build reads `episodes_view`, which returns null until `publish_at <= now()`; HTML scan test; browser read at the minute uses DB clock |
| **Hidden episode's link stays in a built page** | Info disclosure | Gateway hidden list 404s doc and RSC at once; rebuild removes it. YouTube-side visibility is out of reach (accepted) |
| **Forged cookie reaches a walled page** | Spoofing | Signature required (part c 8/8). Forged, wrong key, HS256, `none`, unknown kid: no `user` class. Test each against the wall |
| **Direct read of `/__pages/...`** bypasses the wall | Elevation | `run_worker_first` + refuse; test no HTML outside the prefix; a W-layer curl per kind |
| **Path tricks** (`/en/../__pages`, encoded slashes, case, `.rsc` appended, `..%2f`) to reach another file | Tampering | Map only from a parsed, normalized path; reject `%2f`, `..`, dots in slugs; hidden and wall checks use the same normalized value |
| **Serving RSC to an anon** by adding `rsc: 1` | Elevation | Wall runs before kind selection |
| **Rebuild trigger abuse** | DoS (burns 3,000 min) | Hook URL only in a Worker secret, never logged; only admin actions and crons reach `requestRebuild`; DO debounce and daily cap; rotate by replacing the hook; hook itself is limited to 10/min |
| **Status route abuse** | DoS | Valid session required; DO answers fast; rate not exposed; counts toward 100k like any request |
| **Malicious content in a rebuild** | Tampering | Build is pinned code; content comes from admin-only writes, already sanitised at render |
| **Newer `main` shipped by a rebuild** | Tampering | Pin branch + live-commit check + ruleset |
| **PR code reading build secrets** (public repo) | Info disclosure | Preview Builds off; verify; separate revocable key |
| **Token handling** | Info disclosure | Hook URL, service key, action key: one numbered step each, Koss's terminal or dashboard, nothing in files or chat; build logs must not echo env (scripts never print values, same as `build-target.mjs`) |
| **Stale wall after ban or revoke** | Elevation | JWT stays valid until `exp` (1 h on local, live value not read). Pages hold no personal data; RLS uses the same JWT. Accepted by moving from `getUser`; report it (Phase 5 D-01) |
| **Open redirect through `next`** | Tampering | `getSafeAuthNextPath` in the browser, unit-tested; gateway builds `next` from its own path only |
| **Header poisoning** | Tampering | Files have no request input; the gateway reads only the cookie, `rsc` headers and method |
