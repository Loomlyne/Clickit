```ts
// src/server/gateway/index.ts (new, pure: relative imports, no cloudflare:)
export type OpenNextHandler = { fetch(request: Request, env: unknown, ctx: unknown): Promise<Response> }
export type GatewayDeps = {
  config: { authCookieName: string; jwksUrl: string; categorySlugs?: string[] }
  verifier: { classify(cookieHeader: string | null, cookieName: string): Promise<{ cls: 'user' | 'anon' | 'bypass'; reason: string }> }
  loadOpenNext: () => Promise<OpenNextHandler>
}
export function handleGateway(request: Request, env: unknown, ctx: { exports?: { Pages?: { fetch(r: Request, init?: { cf?: { cacheKey?: string } }): Promise<Response> } } }, deps: GatewayDeps): Promise<Response>
export function handlePages(request: Request, env: unknown, ctx: unknown, deps: { loadOpenNext: () => Promise<OpenNextHandler>; now: () => number }): Promise<Response>
```
Gateway order: stripInboundInternal -> classifyRequest -> (redirect: answer with `Cache-Control: private, no-store` and `x-clickit-path: gateway`) | (direct: OpenNext with real ctx, `x-clickit-path: direct`) | (candidate: verifier.classify -> bypass => direct with the original cookies; user && authPath => direct; else buildCacheKey with knownCategories from config.categorySlugs (empty set when absent); !ok => direct; else prepareCachedRequest -> ctx.exports.Pages.fetch(prepared, { cf: { cacheKey } }) -> toBrowserResponse, `x-clickit-path: cached`). If ctx.exports.Pages is missing, go direct. If the Pages call throws, return a 503 with `Cache-Control: private, no-store` (do not re-render directly: a second render would double the CPU on Free).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> default entrypoint | Only the default export is routable; Pages is reachable only via ctx.exports |
| server action / cron -> Pages RPC | Invalidate and purge cross into the cached entrypoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-50 | Spoofing | forged or expired JWT | mitigate | verifier from session.ts; bypass goes direct with original cookies (proxy refreshes or clears); unit-tested |
| T-02.1-51 | Information disclosure | cross-user leak via cached path | mitigate | Class in key; prepared request has no cookies; inbound x-clickit-* stripped on every path; user /auth direct |
| T-02.1-52 | Tampering | cache poisoning | mitigate | Only prepareCachedRequest output reaches Pages; key from buildCacheKey; tests in -02/-03 and here |
| T-02.1-53 | Tampering | open redirect via ?next= | mitigate | buildCacheKey rejects unsafe next (bypass); gateway redirects only to fixed locale targets |
| T-02.1-54 | Information disclosure | cookie leakage | mitigate | Pages responses lose Set-Cookie; gateway adds only NEXT_LOCALE |
| T-02.1-55 | Denial of service | purge abuse | mitigate | RPC is not reachable from the internet; only tags accepted; callers added in 02.1-19 are admin actions and the cron |
| T-02.1-56 | Denial of service | Pages failure causing a second full render | mitigate | No direct re-render after a Pages failure (503 no-store); stale-if-error covers stored entries |
| T-02.1-57 | Elevation of privilege | admin pages through the cache | mitigate | /admin* classified direct; default entrypoint has cache off |
