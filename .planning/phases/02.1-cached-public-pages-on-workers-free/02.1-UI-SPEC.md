## What changes, and for whom

| Visitor | What changes |
|---------|--------------|
| Signed out | **Nothing.** The header shows the Sign In button, and the landing shows Sign In + Start free, at first paint, exactly as today (the signed-out copy is rendered for the `anon` class). |
| Signed in (viewer or admin) | For about 0.1-0.3 s after first paint, the three areas below show same-size placeholders. Then they fill in place: no layout shift, no button flip. |

## 1A — Header avatar slot (signed-in class)

- **First paint.** An empty circle the same size as `UserAvatar`: 30px, `rounded-full`, `border border-[var(--line-2)]`, filled `--bg-2`. No letter, no pulse animation (a static circle reads as "loading" without drawing the eye). It is not interactive until filled.
  - `aria-hidden="true"` while empty.
  - The real `UserAvatar` (a button with the `nav.userMenu` label) replaces it.
- **Filled.** The existing `UserAvatar`: the photo, else the initial on the `--chart-5`→`--chart-2` gradient. The dropdown is unchanged: email, Profile, Admin (admins only, still from the browser as today), Sign out.
- **Where.**
  - Desktop header right side (`navbar.tsx`, the `AuthSection` default layout).
  - Mobile sheet (`layout="sheet"`): the sheet shows its existing two-button grid as placeholders of the same height (`h-11`, `rounded-full`, `--bg-2`) until filled.
  - Coming-soon minimal header (`layout="minimal"`): the same 30px empty circle.
- **RTL.** It mirrors via the existing `ms-auto` and logical properties. The circle sits at the physical left in AR, as the avatar does today.
- **Signed-in visitor whose session turns out invalid.** The circle is replaced by the Sign In button (same as signing out today).

## 2A — Show page personal controls (signed-in class)

- **First paint.**
  - Play is live and unchanged.
  - My List and Like render as `Skeleton` pills of the same size as the real buttons (same height and width as the `watchlist-toggle-button` / like button for that breakpoint, `rounded-full`), not clickable, `aria-hidden`.
  - Episode rows render with no progress bar.
- **Filled.**
  - The real buttons appear in their true state: "In your list" ✓ or "Add to List" +, Like on or off.
  - Progress bars fade in (opacity 0→1, 150 ms, `motion-reduce` = no fade) at their real width on `--primary`.
- **Episode page** (`/watch/<episode>`): the same rule for My List, Like and the episode list progress. The player does not start until the resume position is known (≤ about 0.3 s). It shows its existing loading state meanwhile, then starts at the saved second.
- **Signed out.** Unchanged: "Add to List" shows and opens sign-in, as today.
- **AR.** The same, with the existing Arabic strings (`show.addToList` "إضافة إلى القائمة", `show.removeFromList` "في قائمتك", `show.like` "إعجاب"). Bars grow from the inline start.

## 3A — Watch home "Continue watching" (signed-in class)

- **First paint.** The rail title ("Continue watching" / "تابع المشاهدة") plus a row of `Skeleton` cards at the exact height and count of the real rail's first visible cards for the breakpoint, so the next rail does not move.
- **Filled.**
  - The real cards with progress bars, in place.
  - If the viewer has nothing to continue, the placeholder row is removed (today the rail is simply absent for them). That is the only height change, and only for viewers with an empty history.
- **Signed out.** No rail and no placeholder (unchanged).

## Copy

No new strings. Placeholders carry no text. Existing keys only: `common.signIn`, `nav.userMenu`, `nav.profile`, `nav.admin`, `common.signOut`, `show.addToList`, `show.removeFromList`, `show.like`, `home.continueWatching`.

## Interaction and accessibility

- Placeholders are `aria-hidden` and not focusable. Focus order is unchanged once filled.
- No layout shift from any placeholder (CLS 0 for these three areas). Each placeholder has the same box as the element it stands in for.
- `prefers-reduced-motion`: no pulse, no fade.

## Other visible effects (no picture, recorded for UAT)

- The hero video is picked by the browser (phone or desktop file). A phone may show the poster frame briefly before the video starts.
- Admin content edits show after one refill. The coming-soon switch takes effect at once.
- The `/en` → `/en/portfolio` hop drops `utm_*` from the URL.
- Arabic footer, FAQ and legal text follow the URL locale.

## Admin rebuild status bar (D-72, signed by Koss 2026-10-31, picture A)

One line at the top of every admin page, EN and AR, in the existing admin tokens (`--muted` surface, `--border` hairline, `--radius`). It reports the real rebuild state and is shared by all admins.

| State | Icon colour | Copy |
|---|---|---|
| Waiting | `--primary` | Saved. Viewers will see it in a few minutes. |
| Done | `--foreground` | Your changes are live. |
| Failed (after one automatic retry) | `--destructive`, with a `--destructive` border | Couldn't update the site. Viewers still see the last version. Button: Try again (`--primary`) |

Try again must start a real rebuild. Arabic copy goes through the normal translation review.
