<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser session -> Supabase (RLS) | Personal reads now run with the visitor's own token |
| shared HTML -> every visitor | Must hold no personal state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-110 | Information disclosure | cross-user leak of watchlist/like/progress in shared HTML | mitigate | No server user read; provider fetches in the browser under RLS; byte-identical check in 02.1-21 |
| T-02.1-111 | Elevation of privilege | browser reading another user's rows | mitigate | Queries filter by the session's own user id and RLS enforces it (existing policies; writes were already browser-side) |
| T-02.1-112 | Spoofing | forged or expired JWT | mitigate | The browser client validates via Supabase; an invalid session resolves to anon (signed-out buttons) |
| T-02.1-113 | Tampering | cache poisoning through slug | mitigate | Gateway route regex for slugs; unknown slug gives 404 (not stored) |
| T-02.1-114 | Tampering | open redirect via ?next= on anon clicks | mitigate | Unchanged: next is the current pathname, applied through getSafeAuthNextPath on the auth form |
| T-02.1-115 | Information disclosure | cookie leakage | accept | No cookie handling added |
</threat_model>
