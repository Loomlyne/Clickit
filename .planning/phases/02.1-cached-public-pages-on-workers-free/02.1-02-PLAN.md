<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> gateway | Path, query, headers and cookies are attacker-controlled |
| gateway -> cached entrypoint | Only what prepareCachedRequest forwards may influence a shared entry |
| gateway -> proxy (x-clickit-class) | The proxy trusts the class header only on the cached path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-10 | Tampering | key.ts (cache poisoning through query or router headers) | mitigate | Strict param allowlist, unknown params bypass, router header values validated (segment regex, prefetch '1' only), key built from normalised values |
| T-02.1-11 | Tampering | headers.ts (poisoning through Host family, Accept-Language, Cookie) | mitigate | Strip list covers Cookie, Authorization, Accept-Language and the Workers Cache anti-poison headers; unit test asserts each |
| T-02.1-12 | Information disclosure | cross-user leak via class confusion | mitigate | Class is in the key; inbound x-clickit-* always removed; readTrustedClass refuses when cookies or authorization are present |
| T-02.1-13 | Spoofing | forged or expired JWT reaching the cached path as user | mitigate | Class comes only from session.ts (02.1-01); classify marks authPath so user-class /auth goes direct |
| T-02.1-14 | Tampering | open redirect via ?next= | mitigate | isAcceptedAuthNext uses getSafeAuthNextPath with a sentinel; rejected values bypass; tests for //, /\\, absolute URL, encoded slashes, control chars, /auth loops |
| T-02.1-15 | Information disclosure | utm or click ids stored in bodies or Location | mitigate | Removed from forwardUrl and key; locale-root 308 drops them |
| T-02.1-16 | Denial of service | key cardinality explosion | mitigate | Unknown params, unknown categories and malformed segments bypass instead of creating entries |
| T-02.1-17 | Information disclosure | cookie leakage into the render | mitigate | Cookie removed before the cached entrypoint; NEXT_LOCALE handled by the gateway (02.1-03) |
</threat_model>
