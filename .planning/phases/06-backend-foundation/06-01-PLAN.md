    **Step 3: Create RLS policies migration** (`supabase/migrations/20260401000001_create_rls_policies.sql`)

    **is_admin() function** (AUTH-05, per D-09 -- reads from app_config table, NOT hardcoded UUID):
    - `security definer`, `stable`, `language sql`, `set search_path = ''`
    - Body: `select (select auth.uid()) = (select admin_user_id from public.app_config where id = 1)`
    - This function reads the admin UUID from the `app_config` table at runtime. To change the admin, simply run: `UPDATE public.app_config SET admin_user_id = 'new-admin-uuid' WHERE id = 1;` -- no migration or function replacement needed.
    - Include comment: `-- Admin is identified by app_config table lookup (per D-09)`
    - Include comment: `-- To change admin: UPDATE public.app_config SET admin_user_id = 'new-uuid' WHERE id = 1;`

    **app_config policies:**
    - "Anyone can read app_config": SELECT for anon,authenticated (the admin_user_id is a UUID, not sensitive -- RLS on other tables does the actual gating)
    - "Only service_role can update app_config": No INSERT/UPDATE/DELETE policies for authenticated role. Only the service_role client (admin.ts, which bypasses RLS) can modify this table. This prevents any user from promoting themselves to admin.

    **shows policies** (FOUN-03, AUTH-04):
    - "Public can view published shows": SELECT for anon,authenticated WHERE status in ('now-streaming', 'coming-soon')
    - "Admin can view all shows": SELECT for authenticated WHERE is_admin()
    - "Admin can insert shows": INSERT for authenticated WITH CHECK is_admin()
    - "Admin can update shows": UPDATE for authenticated USING+WITH CHECK is_admin()
    - "Admin can delete shows": DELETE for authenticated USING is_admin()

    **seasons policies:**
    - "Public can view seasons of published shows": SELECT for anon,authenticated WHERE exists(shows with status in ('now-streaming','coming-soon'))
    - Admin CRUD same pattern as shows

    **episodes policies:**
    - "Public can view published episodes": SELECT for anon,authenticated WHERE status in ('published','coming-soon') AND exists(shows with public status)
    - Admin CRUD same pattern

    **profiles policies:**
    - "Users can view own profile": SELECT where auth.uid() = id
    - "Users can update own profile": UPDATE where auth.uid() = id (both USING and WITH CHECK)

    **watch_progress policies:**
    - "Users can view own progress": SELECT where auth.uid() = user_id
    - "Users can upsert own progress": INSERT with check auth.uid() = user_id
    - "Users can update own progress": UPDATE where auth.uid() = user_id

    **watchlist policies:**
    - "Users can view own watchlist": SELECT where auth.uid() = user_id
    - "Users can add to watchlist": INSERT with check auth.uid() = user_id
    - "Users can remove from watchlist": DELETE where auth.uid() = user_id
