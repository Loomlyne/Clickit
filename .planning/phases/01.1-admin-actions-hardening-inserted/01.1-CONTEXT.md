<decisions>
## Implementation Decisions

### Scope
- **D-01:** Fix all 21 high/medium findings (2 high, 19 medium). Fix a low finding only when the fix is a line or two inside code already being touched. All other lows go to Deferred.
- **D-02:** The 50 findings and their line numbers are in `.planning/research/ADMIN-ACTIONS-AUDIT-DRAFT.md`. Line numbers drift; match by action name.

### Locked earlier (roadmap sign-off, 2026-10-11)
- **D-03:** New SVG uploads are rejected (PNG/WebP/AVIF only); already-stored SVGs untouched. `sanitizeSvgUpload` is removed with its callers.
- **D-04:** `deleteShowPermanently` and `deleteEpisodePermanently` require the item to be archived.
- **D-05:** Atomicity by app-level ordering and compensation. No migration, no Postgres functions.

### Failure and rollback
- **D-06:** When a multi-step write fails midway, compensation restores the earlier steps, the admin gets an error, and one audit row records the failed attempt. If the undo itself fails, the audit row states exactly what was left in place.
- **D-07:** Never swallow a Supabase error: every update/delete result is checked and returned.

### Archive-first delete UI
- **D-08:** The permanent-delete control appears only on archived items. The server also refuses a direct call with a clear error. No dead control.

### Testing
- **D-09:** Extract schemas and guards into pure functions with unit tests (`tests/unit/*.test.ts`, run by `npm run test:unit`). The riskiest flows (conflict restore, `updateShow` category sync, `archiveShow`, `restoreShow`) get a small in-memory fake Supabase client that can force a mid-flow failure. Each failing input has a test that failed before the fix.

### Claude's Discretion
- Schema file layout, error message wording (reuse the existing return shape), and how compensation is sequenced per action.

</decisions>
