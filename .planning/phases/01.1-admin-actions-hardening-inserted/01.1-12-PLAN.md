<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> signed upload URL -> Supabase storage | the browser reports file size and type; the stored object is what counts |
| admin browser -> image upload actions | file bytes and declared MIME are attacker-controllable |
| server -> public site | uploaded images are served on the public domain |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-48 | Denial of service | saveHeroVideoUpload | mitigate | verifyUploadedVideoSize reads the stored size via storage info() before download and removes oversize objects; blob size checked again |
| T-01.1-49 | Tampering / stored XSS | uploadSiteImage/uploadSocialIcon | mitigate | checkImageUpload refuses SVG by declared type and by sniffed bytes; served MIME is the sniffed one (D-03) |
| T-01.1-50 | Repudiation | hero video actions | mitigate | logAudit after every successful hero change |
| T-01.1-51 | Tampering (IDOR / path) | content and upload actions | mitigate | parseId on every id; showId validated before it builds a storage path; source-scan test |
| T-01.1-52 | Tampering (integrity) | updateTopTicker | mitigate | strict translation, no English fallback; untranslated count returned to the UI |
| T-01.1-53 | Denial of service | orphaned oversize uploads never saved | accept | an upload whose save is never called stays in storage; flagged to Koss, bucket lifecycle is out of scope (no live access) |
</threat_model>
