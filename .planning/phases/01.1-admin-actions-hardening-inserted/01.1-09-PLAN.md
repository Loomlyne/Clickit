<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> schedule actions | showId is client-controlled |
| cron publish-scheduled -> episodes | concurrent writer that can publish an episode between plan and apply, or between apply and unschedule |
| admin_audit_log diff -> unschedule | stored JSON drives writes, so it is parsed before use |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-36 | Tampering (partial write) | applyShowScheduleCore | mitigate | sequential compensated steps; failed audit row (D-05, D-06) |
| T-01.1-37 | Tampering (race) | applyShowScheduleCore | mitigate | conditional update (show_id, archived=false, status != published); zero rows aborts and undoes |
| T-01.1-38 | Repudiation | apply/unschedule | mitigate | audit rows carry every episode id with previous and new values, plus skipped ids with reasons |
| T-01.1-39 | Tampering | unscheduleShowCore legacy path | accept | shows scheduled before this phase have no record; fallback keeps today's reset but is now fully audited (flagged to Koss) |
| T-01.1-39b | Tampering (stale undo) | unscheduleShowCore | mitigate | revert only when status and publish_at still equal what the scheduler wrote (instant compare), conditional update on the read values |
| T-01.1-39c | Tampering (bad stored data) | unscheduleShowCore | mitigate | bulkScheduleRecordSchema.safeParse before any write; unreadable record refused with a failed audit row; no fallback to older records |
