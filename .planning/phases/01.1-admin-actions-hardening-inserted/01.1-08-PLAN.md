Move archiveEpisode, restoreEpisode, deleteEpisodePermanently and reorderEpisode into a tested core: archive-first permanent delete with a pending audit row before the delete and a terminal row after it (D-04, D-06), reorder through the existing atomic database function instead of a three-step app swap, ids and direction parsed, and counts that stay correct. Purpose: ADMIN-02, ADMIN-03, ADMIN-04 (success criteria 2, 3, 4 for episodes).
Output: src/lib/admin/episode-lifecycle.ts and its tests.

Why the RPC (review issue 7): supabase/migrations/20260724115941_restrict_public_episode_access.sql already defines public.reorder_episode(uuid, text). It takes a per-season advisory lock, skips archived neighbours, refuses an archived current episode and does the temp-number swap inside one transaction. Rebuilding it in app code would reintroduce the race and the half-swap risk. D-05 forbids adding migrations or Postgres functions; this plan adds neither, it calls a function that is already in the repo's migrations. No migration file is created or edited.
</objective>

public.reorder_episode (supabase/migrations/20260724115941_restrict_public_episode_access.sql, read lines around "create or replace function public.reorder_episode"):
- signature reorder_episode(p_episode_id uuid, p_direction text) returns table (show_id uuid, season_id uuid, episode_id uuid, episode_number integer); episode_number in the result is the ADJACENT episode's old number (= the current episode's new number)
- security invoker; execute granted only to service_role (the admin client)
- errors: 22023 'Reorder direction must be up or down'; P0002 'Episode not found'; P0001 'Archived episodes cannot be reordered'; P0001 'No adjacent active episode to swap with'; 22003 'Cannot reserve a temporary episode number'
- body: pg_advisory_xact_lock(hashtextextended(season_id::text, 3071971)); current row FOR UPDATE; nearest non-archived neighbour (up: lower number, order desc limit 1; down: higher number, order asc limit 1) FOR UPDATE; temp = min(episode_number in the season) - 1; three updates inside the function, so the swap is atomic
- not referenced anywhere in src today; not present in src/lib/database.types.ts Functions, so db.rpc('reorder_episode', ...) needs one narrow typed cast (do not regenerate database.types.ts)
- live status: .planning/research/ARCHITECTURE.md (Pattern 5) says whether this migration is applied on live is unknown. The local stack applies it on supabase db reset --local. A read-only check on live is a Ship prerequisite (plan 13 records it); this plan does not touch live.

Legacy behaviour in src/app/[locale]/admin/actions.ts (by name):
- archiveEpisode(id, showId): update archived=true by id; show episode_count from the CLIENT showId (archived=false), error ignored; season count not updated; no audit; no cache bump of 'shows'.
- restoreEpisode(id): reads id, show_id, title; un-archives; show count (archived=false) error ignored; audit 'restore'; season count not updated.
- deleteEpisodePermanently(id): reads title, show_id ignoring the error; deletes (CASCADE watch progress/likes) with no archived check; show count error ignored; audit after the delete.
- reorderEpisode(episodeId, direction): reads current (id, episode_number, season_id, show_id) and returns 'Episode not found' when missing; neighbour by episode_number +/- 1 in the season without an archived filter, 'No adjacent episode to swap with' when none; three updates (current -> -1, neighbour -> current number, current -> neighbour number) all errors ignored; no audit.
DB: episodes unique (season_id, episode_number) including archived rows.
