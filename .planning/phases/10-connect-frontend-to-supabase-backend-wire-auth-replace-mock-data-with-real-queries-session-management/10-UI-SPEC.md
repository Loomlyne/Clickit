## Typography

This phase introduces no new type roles. All copy uses tokens already established in the design system.

| Role | Size | Weight | Line Height | Usage in This Phase |
|------|------|--------|-------------|---------------------|
| Body | 16px (text-base) | 400 (regular) | 1.5 (leading-relaxed) | CTA banner body copy, series empty state body |
| Label | 11px (text-[11px]) | 500 (font-medium) | 1.4 | Small caps labels: "Seasons", "Coming soon", "Now streaming", "Clickit membership" |
| Heading | 30px (text-3xl) | 600 (font-semibold) | 1.2 | Series empty state headline ("Episodes are being prepared.") |
| Display | clamp(2.4rem, 5vw, 4.4rem) | 600 (font-semibold) | 0.96 | CTA banner headline (all three stages) |

Label styling pattern (reused from search, watch, hero):
```
text-[11px] font-medium uppercase tracking-[0.28em] text-white/38
```

Display styling pattern (existing CTA banner):
```

font-size: clamp(2.4rem, 5vw, 4.4rem)
```

### CTA Banner Architecture

`CtaBanner` stays a server component (no `'use client'` directive). It becomes `async` and calls `getCatalogStage()` internally. The `CTA_COPY` object maps `zero | growing | full` to { label, headline, body, primaryLabel, primaryHref, secondaryLabel, secondaryHref }. All visual structure (rounded card, brand bar, radial glow, button layout) remains identical -- only text content changes per stage.

## Interaction States

| State | Trigger | Visual Result |
|-------|---------|---------------|
| Browse empty | `streaming.length === 0 && comingSoon.length === 0` | Invisible -- user sees `/` (marketing page) via server redirect |
| Series no seasons | `viewSeasons.length === 0` | Text-only empty state below hero, above "More Like This" rail |
| CTA stage zero | `getCatalogStage()` returns `zero` | CTA banner renders pre-launch copy with `/auth` primary CTA |
| CTA stage growing | `getCatalogStage()` returns `growing` | CTA banner renders early-catalog copy with `/browse` primary CTA |
| CTA stage full | `getCatalogStage()` returns `full` | CTA banner renders current copy (no visual change from existing) |
| Series empty state link hover | Mouse over "See what's coming" | Text transitions from `text-white/60` to `text-white` |

No loading states needed -- all rendering is server-side with no client-side data fetching.
No error states needed -- query failures are handled by existing error boundaries.
