## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser -> saveYouTubeApiKey | The plaintext key crosses once, inside a same-origin Server Action |
| server -> admin browser | Only hasKey, last 4 and the last test result cross |
| server -> Vault | Service-role RPC to set_youtube_key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-61 | Information disclosure | admin session stealing the key | mitigate | the UI never receives the key after save: page reads `readYouTubeKeyMeta` (hasKey + last4) only; typed value cleared from state after save; guard test bans `get_youtube_key` in the page |
| T-06-62 | Information disclosure | client read through PostgREST | mitigate | `get_youtube_key` / `set_youtube_key` / `youtube_key_meta` execute only for service_role (06-01, proven locally); the browser has no service-role client |
| T-06-63 | Information disclosure | key in logs | mitigate | no `console.` in the save core or action block; fixed error messages; tests assert the key and its prefix are absent from results, audit args and logError args |
| T-06-64 | Spoofing / CSRF | saveYouTubeApiKey | mitigate | Next Server Actions reject cross-origin POSTs (no `allowedOrigins` widening, guard test); `requireAdminForYouTube()` first via `runAdminAction` (TODO(phase-5) swaps to requireAdmin + TOTP) |
| T-06-65 | Information disclosure | audit-row leak | mitigate | audit diff holds `kind` and `last4` only; test asserts the full key never reaches the audit writer |
| T-06-66 | Tampering / abuse | repeated saves | mitigate | format check before any DB call; rate limit 10 per admin per hour, fail closed |
| T-06-67 | Denial of service (quota) | Test key | accept | 1 unit per press, admin-only; quota reason shows reset time |
| T-06-68 | Repudiation | key changes and tests | mitigate | each save and test is an audit row naming the admin |
</threat_model>
