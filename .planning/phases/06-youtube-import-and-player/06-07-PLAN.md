<objective>
Implement D-17: the daily re-check of every stored episode video, the shared "Can't play" rule used by the admin badge and dashboard, and the server-side YouTube client factory every admin action reuses.

Purpose: stored YouTube data stays refreshed within the Developer Policies' 30-day window and broken episodes are flagged for admins, within Workers Free limits (about 8 subrequests per run; RESEARCH Pattern 11, Pitfall 11).

Decision needing Koss at the plan gate (D-17 interpretation, RESEARCH A9 / Open Question 2): the re-check refreshes status, length and checked-at only; titles and descriptions are treated as Clickit editorial content after import and are never refreshed (consistent with D-05). This is a reading of policy III.E.4, not a quote.

Cron budget note: Free allows 5 Cron Triggers per account; Phase 2 uses 2, this adds 1. The trigger string goes live only when Phase 3's cutover list is applied; this plan does not switch any cron on.
</objective>
