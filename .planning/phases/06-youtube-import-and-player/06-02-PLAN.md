## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin input -> parsers | Pasted links are untrusted text |
| Worker -> googleapis.com | Key leaves the Worker in a request header |
| YouTube response -> app | Titles/descriptions are third-party text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07 | Tampering / SSRF | urls.ts | mitigate | host allow-list, http/https only, ids extracted and matched to strict regex; the client builds URLs from ids only, fixed base URL |
| T-06-08 | Information disclosure | client.ts errors | mitigate | fixed messages per code, no URL/body/key in errors; header transport; test asserts the key never appears |
| T-06-09 | Information disclosure | OpenNext fetch cache | mitigate | `cache: 'no-store'`, no `next.revalidate`, so key-bearing requests never reach the R2 incremental cache |
| T-06-10 | Tampering (stored XSS) | YouTube titles | mitigate | stored as plain text, capped lengths, rendered by React as text only (no dangerouslySetInnerHTML anywhere in this phase) |
| T-06-11 | Denial of service (quota) | client batching | mitigate | 50 ids per videos.list, no search.list, paging bounded by callers (cap 200 in 06-05) |
</threat_model>
