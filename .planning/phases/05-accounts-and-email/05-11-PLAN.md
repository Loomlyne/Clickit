Payload contract (jsonb on `email_outbox.payload`), unchanged:
- welcome: `{}`
- digest: `{ shows: [{ title, title_ar, slug, image_url, episodes: [{ id, season_number, episode_number, title, title_ar }] }], total_shows }`
- support_ack: `{}` (static)
- support_admin: `{ message_id, name, email, subject, message }`
- newsletter_confirm: `{ subscriber_id }`
Row: `{ kind, locale, payload, idempotency_key, to_user? }` (to_user from the claimed row, 05-08; the digest's unsubscribe link needs it).
Context: `{ siteOrigin, links: { unsubscribe(userId): Promise<string>, newsletterConfirm(subscriberId): Promise<string> } }` (signing happens in 05-16/05-19 with `EMAIL_LINK_SECRET`). `renderAppEmail` keeps this exact signature, so 05-16's `deps.ts` is unchanged.

Superseded wording: UI-SPEC 7 ("app emails rendered in the queue consumer") and D-38 ("Emails render only in the consumer") are superseded by the 2026-10-21 pre-render decision: app emails are rendered at build time and only filled in the consumer; nothing is rendered or filled in a request handler. (The controller adds the same note to those files.)

Design (revision 4 after the 05-07 spike, revision 5 after the Sonnet review):
- Where the HTML is made: React Email runs only at build time and in tests. `scripts/build-app-templates.mjs` renders every kind x locale (digest twice: `base` without and `more` with the "See all" link) through the 05-07 shell with slot sentinels in place of row data, and writes `src/generated/app-email-templates.json`. The file is **checked in** (same pattern as 05-10's `supabase/templates/*.html`) and guarded by a drift test in `test:unit` (part of `gate:local`). It is not an npm script: 05-10 adds `emails:build:auth` to package.json in the same wave 3, and two plans editing package.json in one wave is a conflict; the rebuild command is in the script header and in the drift test's failure message.
- Why JSON under `src/generated/`: the generated HTML holds the email hex colours (from EMAIL_TOKENS). A `.ts` file under `src/` would trip `clickit/no-raw-design-values` (it lints `src/**/*.{ts,tsx}` string literals), and anything under `src/emails/` would trip 05-07's source guard (no hex under src/emails). JSON is data, like the auth HTML.
- Slots: sentinels `__clk_<type>_<name>__` (type `txt` text, `url` URL, `pre` preheader, `blk` row block; name `[a-z][a-z0-9]*`). Only lowercase letters, digits and underscores, so React never escapes them and html-to-text never changes them (the builder throws if an upper-cased `__CLK_` form appears in a text template).
- Fill is a single pass: `template.replace(new RegExp(SLOT_SOURCE, 'g'), callback)`, a fresh regex per call (a shared `/g` regex keeps `lastIndex` between calls). Required slots are read from the template itself (`slotsOf(template)`) and checked against the given values before filling; the output is never scanned again. A visitor's text that looks like a sentinel is therefore inserted (escaped) and left alone.
- Logic that slots cannot express, and how each is handled: (1) "See all" only when more than 3 shows -> two pre-rendered variants `digest:base` and `digest:more`; (2) the repeating show list and nested episode list -> row templates filled per item, joined, inserted as the one trusted block; (3) optional thumbnail -> two show-row templates, `show` and `shownoimage`, both cut from direct renders; the model picks `shownoimage` when image_url is unusable; (4) the Arabic title fallback, the 3x3 caps and the `S{season} E{episode} - {title}` line -> computed in the shared model before either path renders; (5) react-email `Preview` pads the hidden preheader with `200 - length` copies of a 7-character whitespace string, so the one dynamic preheader (E9 "New message from {name}.") is a `pre` slot that reproduces the padding; (6) the 48-hour and 7-day lines -> baked at build time with a plural-category guard test. Nothing needs rendering at send time; if the executor finds a case that does, stop with `NEEDS CONTROLLER: <list>` instead of improvising.
- Plurals (controller condition 2): the signed copy has no runtime-variable count (E7 has no "N new episodes" line; season and episode numbers are numerals in `S{season} E{episode}`, Latin digits in both locales as the signed AR string shows). The only plural-sensitive numbers are build constants: SUPPORT_REPLY_HOURS = 48 (G25 = A) and NEWSLETTER_CONFIRM_TTL_DAYS = 7. The builder fills them with the same `fill()` the direct path uses; a test pins `new Intl.PluralRules(locale).select(n)` (en: 'other' for both; ar: 48 -> 'many', the singular-noun form "ساعة" in the signed AR string is correct for 11-99; 7 -> 'few', "أيام" is correct for 3-10).
- Empty values: the model rejects a required field that is empty after trim as `bad payload <kind>` (the contact form already requires name >= 2, subject >= 3, message >= 10 characters, so this only catches corrupt rows; the support message itself stays saved in the admin inbox). An empty `title_ar` is not an error: it falls back to `title`.
- Controller test names (run them with `node --experimental-strip-types --test --test-name-pattern="condition" tests/unit/email-template-fill.test.ts tests/unit/app-email-parity.test.ts`): "condition 1: hostile support_admin name", "condition 1: sentinel text in values is inert", "condition 1: sentinel text in values is inert end to end", "condition 2: plural guard", "condition 3: digest parity", "condition 3: all kinds parity".

Output: model, fill module, React builders, direct path, Worker-safe renderer, builder script, generated JSON, screenshot script, four test files, four PNGs.
