<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> server actions | email, code, password, next, captcha token are attacker-controlled |
| server -> Supabase Auth | sign-in calls from the Worker's egress IP |
| server -> email links | origin and next become clickable links |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-21-01 | Spoofing (code brute force) | verifyCode | mitigate | 6-digit code, 15-min expiry, 5 failures per email per 15 min lock, Supabase verify limits |
| T-05-21-02 | Denial of service (email bombing) | sendCode / reset | mitigate | Turnstile via Supabase captcha, per-IP and per-email limits, Supabase per-user 60 s window |
| T-05-21-03 | Information disclosure (enumeration) | sendCode / reset / signUp | mitigate | identical responses for new and existing emails; reset always ok |
| T-05-21-04 | Tampering (open redirect / host injection) | emailRedirectTo, next | mitigate | getSafeAuthNextPath; origin from env or an allow-listed host only; Supabase redirect allow-list |
| T-05-21-05 | Elevation of privilege | leaked passwords | mitigate | HIBP check before signUp and every password set (fail open logged, D-11) |
| T-05-21-06 | Repudiation (duplicate welcome) | afterSignIn | mitigate | claim_welcome conditional update + unique key; tested |
| T-05-21-07 | Tampering | user_metadata.locale | accept | user-editable; used only to pick the email language, never for authorisation |
</threat_model>
