  <name>Task 1: HMAC link tokens (D-32, D-35)</name>
  <files>src/server/email/links.ts, tests/unit/unsub-link.test.ts</files>

  </read_first>
  <behavior>
    - sign('unsub_digest', userId, null) then verify(token, 'unsub_digest') -> { ok: true, id: userId }
    - sign('newsletter_confirm', subId, now+7d) verifies before expiry; at expiry+1 s -> { ok: false, reason: 'expired' }
    - a newsletter_confirm token verified as 'unsub_digest' -> { ok: false, reason: 'invalid' }
    - one flipped character in payload or signature -> invalid; empty or missing secret -> sign throws, verify returns { ok: false, reason: 'unavailable' }
    - token is URL-safe (only [A-Za-z0-9_.-]) and contains no '=' or '+'
  </behavior>
  <action>
    Pure module, no imports. `LINK_KINDS = ['unsub_digest', 'newsletter_confirm'] as const`, `NEWSLETTER_CONFIRM_TTL_DAYS = 7`. Token = base64url(`${kind}.${id}.${expSec|0}`) + '.' + base64url(HMAC-SHA256(secret, that payload)). `signLinkToken(input: { kind, id, expSec: number | null, secret })` and `verifyLinkToken(token, expectedKind, secret, nowSec)` returning `{ ok: true; id } | { ok: false; reason: 'invalid' | 'expired' | 'unavailable' }`. Verify with `crypto.subtle.importKey('raw', ..., { name: 'HMAC', hash: 'SHA-256' }, false, ['verify'])` and `crypto.subtle.verify` (constant time). `id` must match a UUID regex or verify returns invalid. Header comment: kind separation stops replay across uses; never log tokens.
  </action>
