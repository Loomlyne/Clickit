### 3. Edge Arrow — Next Episode

**Element:** `<button>`
**Condition:** Only rendered when `currentNextEpisode !== null` (not rendered = not in DOM)
**Position:** `fixed right-3 top-1/2 -translate-y-1/2 z-20`
**Size + Shape:** `size-10 rounded-full`
**Background:** `bg-black/40 backdrop-blur-sm`

**Icon:** `<ChevronRight className="size-5 text-white" />`
**aria-label:** `"Next episode"`
**onClick:** `handleEpisodeSwitch(currentNextEpisode)`

**Critical:** Use `currentNextEpisode` (state), NOT `nextEpisode` (initial prop). After in-session episode switch, the prop is stale.

### 4. useIdleTimer Hook (new file)

**File:** `src/hooks/use-idle-timer.ts`
**Signature:** `useIdleTimer(delay: number): { isIdle: boolean; resetTimer: () => void }`
**Delay:** 3000ms
**Timer type:** `ReturnType<typeof setTimeout>` — bare `setTimeout`, not `window.setTimeout`
**Initial state:** `isIdle = false` (chrome visible on mount)
**Cleanup:** clears timer on unmount

## States

### Chrome Visibility State Machine

```
VISIBLE (isIdle=false)
  → user idle for 3000ms → HIDDEN (isIdle=true)
  → any pointer/touch/key event → VISIBLE
  → video pauses (state=2) → VISIBLE (resetTimer called)

HIDDEN (isIdle=true)
  → any pointer/touch/key event → VISIBLE
  → video pauses (state=2) → VISIBLE
```

| State | CSS Classes | pointer-events | aria-hidden |
|-------|-------------|----------------|-------------|
| Visible | `opacity-100 pointer-events-auto` | auto | false |
| Hidden | `opacity-0 pointer-events-none` | none | true |

### Icon Button States

| Element | Default | Active (filled) |
|---------|---------|-----------------|
| Bookmark | `text-white/70`, Bookmark outline | `text-white fill-white` |
| Heart | `text-white/70`, Heart outline | `text-pink-400 fill-pink-400` |
| Share2 | `text-white/70`, always outline | — (no active state) |

### Edge Arrow Render States

| Condition | Prev Arrow | Next Arrow |
|-----------|-----------|-----------|
| `prevEpisode !== null` | Rendered + fades with chrome | — |
| `prevEpisode === null` | Not in DOM | — |
| `currentNextEpisode !== null` | — | Rendered + fades with chrome |
| `currentNextEpisode === null` | — | Not in DOM |

## Interaction Flows

### Flow 1: Chrome Reveal on Pointer Move

1. User moves pointer anywhere on `WatchShell` root div
2. `onPointerMove` fires → `resetTimer()` called
3. `isIdle` set to `false` → `chromeClass` = `opacity-100 pointer-events-auto`
4. Top overlay and any rendered edge arrows become visible (200ms fade in)
5. 3000ms countdown starts
6. If no further interaction: countdown expires → `isIdle = true` → chrome fades out (200ms)

### Flow 2: Chrome Reveal on Touch (Mobile)

1. User taps anywhere on shell root div (outside iframe bounds not captured — see note below)
2. `onPointerDown` or `onTouchStart` fires → `resetTimer()`
3. Same as Flow 1 from step 3

Note: Taps inside the YouTube iframe do not bubble to parent (cross-origin). Chrome reveal on iframe tap is NOT guaranteed. The user must tap a shell region (overlay buttons, edge strips, screen edges) to trigger reveal.

### Flow 3: Episode Navigation via Edge Arrow

1. Chrome is visible (user recently interacted)
2. User clicks/taps prev or next arrow button
3. `handleEpisodeSwitch(prevEpisode)` / `handleEpisodeSwitch(currentNextEpisode)` fires
4. `forceFlush()` saves outgoing episode progress
5. `currentEpisode`, `currentNextEpisode` state updates
6. `player.loadVideoById()` swaps video without iframe remount
7. URL updated via `window.history.replaceState`
8. Arrow click itself is a pointer event → `resetTimer()` keeps chrome visible for 3s post-click

### Flow 4: Pause Forces Chrome Visible

1. Video pauses (YouTube native controls or external signal)
2. `onStateChange(2)` fires in `WatchShell`
3. `forceFlush()` + `resetTimer()` called
4. Chrome becomes visible (`isIdle = false`) and 3s countdown starts
5. If user does not move for 3s, chrome hides even while paused

**Note:** This implements "pause shows chrome briefly" not "pause keeps chrome indefinitely." Netflix keeps chrome visible for the full pause duration. Phase 33 uses the simpler `resetTimer()` approach. If indefinite pause visibility is required in a future phase, `useIdleTimer` needs a `keepAlive` boolean param.

### Flow 5: Back Navigation

1. User clicks back button (left side of overlay) — only active when chrome visible
2. Navigates to `/series/{show.slug}` via Next.js `Link` (i18n-aware via `@/i18n/navigation`)
3. Watch route unmounts → `useIdleTimer` cleanup fires, timer cleared

### Flow 6: Watchlist Toggle

1. User clicks Bookmark icon button
2. `toggleWatchlist()` from `useWatchlist` hook fires
3. Optimistic state update: icon fills immediately
4. Supabase mutation runs in background
5. On error: icon reverts, toast (via sonner) — handled by existing hook

### Flow 7: Share

1. User clicks Share2 button
2. `navigator.share({ url: window.location.href })` called (Web Share API)
3. On mobile: native share sheet appears
4. Fallback (if `navigator.share` unavailable): `navigator.clipboard.writeText(window.location.href)` + `toast.success("Link copied")`

## Accessibility

### Keyboard

| Key | Behavior |
|-----|----------|
| Tab | Cycles through visible chrome interactive elements (back link, bookmark, heart, share, edge arrows) |
| Enter / Space | Activates focused button or link |
| Any key | Fires `onKeyDown` on shell root → `resetTimer()` → chrome becomes visible |

`onKeyDown` on the shell root div ensures keyboard-only users can reveal chrome by pressing any key.

### ARIA

| Element | Attribute | Value |
|---------|-----------|-------|
| Top overlay div | `aria-hidden` | `"true"` when `isIdle`, `"false"` when visible |
| Edge arrow buttons | `aria-label` | `"Previous episode"` / `"Next episode"` |
| Back link | `aria-label` | `"Back to {show.title}"` |
| Bookmark button | `aria-label` | Dynamic — see Copywriting Contract |
| Heart button | `aria-label` | Dynamic — see Copywriting Contract |
| Share button | `aria-label` | `"Share episode"` |
| Bookmark button | `aria-pressed` | `true` when `isInList`, `false` otherwise |
| Heart button | `aria-pressed` | `true` when `isLiked`, `false` otherwise |

### Focus Management

- Chrome elements are `pointer-events-none` when hidden (`opacity-0`) — they are still in the DOM but cannot receive pointer focus
- Tab focus CAN reach hidden elements when using keyboard-only navigation. Mitigate: when `isIdle`, set `tabIndex={-1}` on all chrome interactive elements to exclude from tab order

### Color Contrast

- White text on `black/70` scrim: contrast ratio ~8:1 (WCAG AA passes at 4.5:1)
- `text-white/70` on scrim: contrast ratio ~5.6:1 — passes WCAG AA for normal text
- `text-white/50` (S/E badge) on scrim: contrast ratio ~3.5:1 — borderline for small text; acceptable in video chrome context (decorative/supplementary information)
- Edge arrow icon (white on `black/40` circle + backdrop-blur): passes in context; blur increases perceived contrast against bright video frames

### Touch Targets

- Edge arrow buttons: `size-10` = 40×40px — meets WCAG 2.5.5 minimum (44×44 recommended). Consider `min-w-[44px] min-h-[44px]` if audit flags this.
- Icon action buttons: `size-8` = 32×32px container. Minimum WCAG touch target is 24×24px (WCAG 2.5.8 AA). Add `p-2` or `size-10` for stricter compliance if needed.
- Back link: text link with icon — full touch area at least 40px tall via `py-2` padding.

### Critical Constraints

1. `pointer-events-none` MUST be applied atomically with `opacity-0`. Never set opacity-0 without pointer-events-none — the invisible overlay will block YouTube controls.
2. Use bare `setTimeout` / `clearTimeout` — NOT `window.setTimeout`. TypeScript narrows `window.setTimeout` to `never` inside guard blocks. Confirmed project pitfall.
3. Edge arrows use `currentNextEpisode` (state), NOT `nextEpisode` (initial prop). Wrong choice causes stale navigation after in-session episode switch.
4. Overlay event handlers (`onPointerMove`, `onPointerDown`, `onTouchStart`, `onKeyDown`) attach to WatchShell root div, NOT to the YouTubePlayer wrapper. YouTube iframe is cross-origin — events inside it do not bubble.
5. `tabIndex={-1}` on all chrome interactive elements when `isIdle` — prevents tab focus reaching hidden (visually absent) controls.
